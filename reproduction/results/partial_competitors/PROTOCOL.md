# Stronger competitors for PR118

The immediate experiment tests precision-tuned Cholesky and compiled SDD on the existing 128-query Armadillo workload before extending the all-method comparison. This is issue #119, continuing PR #118.

Model, query indices and reference outputs are frozen from `real_partial`: ell=.48, vector component amplitude=1/3, normal noise variance=.04, 32 scalar contacts with variance=.0001 and zero targets. At each N all methods use the same normal observations and contacts. Outputs must remain finite with positive variances and pass max variance/prior error <=1e-4, raw Gaussian CDF error <=1e-3, and fixed validation-calibrated CDF error <=1e-3 against retained float64 dense fields. No clipping, likelihood inflation or physical-parameter tuning is allowed to obtain a speedup.

Cholesky variants: float32 factor with float64 moment accumulation; float64 control using the same shared whitening; if necessary, float32 solves with full-kernel residual correction and iterative refinement. All kernel construction, factorization, cross RHS construction, triangular solves, scalar conditioning and CDF work are timed. The whitened implementation shares the factor/forward solves for mean and covariance. Residual actions are charged when used.

SDD uses the compiled original stochastic dual update with normalized isotropic Matérn kernel and correctly scaled likelihood. All query/contact columns and the three normal-data columns share minibatch kernel rows. Trials vary batch size and learning rate. Checkpoints are assessed against the output gates, not a mean-solve residual requirement. Selected total includes cross construction, solver state/compilation, cumulative updates, final transfer/projection/scalar conditioning and CDF. Earlier checkpoint verification and losing configurations are excluded from selected totals, favoring SDD; wall time is also retained. Nonpassing checkpoints are censored convergence evidence, not accuracy-qualified completion times. Residual-corrected moments are an optional separately timed variant.

The shared-compression extension forms the cross matrix at exactly the 32 contacts and 128 requested queries, then uses a thin SVD. Its threshold is relative to the largest singular value, not a bound on posterior error. It uses no spatial interpolation. H², dense and SDD drivers all expose this option; its full cross construction/SVD cost is charged. The same output gates decide acceptance, including contact conditioning. This is an exploratory alternative, not a replacement for the frozen direct workload or a reason to discard failed compression settings.

Run GPU jobs sequentially and retain the allocated-MIG process audit. New host/runtime identity and a repeated control are recorded before comparing old wall times. Common raw input preparation and CUDA initialization remain excluded. Source snapshots and shared input/reference checksums bind each record. Failed numerical trials remain available. Repeats use separate output files and independent SDD seeds.

If an accuracy-passing dense or SDD method wins this candidate, report that result rather than claiming an all-alternatives H² win. Original Sellán–Jacobson and periodic GeoSPR/NUFFT comparisons then remain a subsequent model-quality comparison. Cheap contact-only variance remains an application-quality control even though it fails full-posterior numerical equivalence.
